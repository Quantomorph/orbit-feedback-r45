ORBIT A1 RUNTIME CONTRACT
platforms: linux, linux2, darwin
  Linux, WSL2 or a Linux container is the supported deployment. macOS is permitted for development because it provides the same flock semantics; it is not a supported deployment target.
filesystems:
  - local filesystems only (ext4, xfs, btrfs, apfs, overlayfs)
  - NFS is NOT supported: flock over NFS depends on the server, the mount options and the client implementation, and a lock that is silently advisory-only would defeat the uniqueness guarantee the journal depends on
  - SMB/CIFS and network shares are NOT supported, for the same reason
why: the journal's append lock is fcntl.flock, which is POSIX-only and is only dependable on a local filesystem. Uniqueness of a durable INTENT and of a FILL is decided inside that lock, so its semantics are a safety property, not a portability detail.
not supported: native Windows (win32/cygwin): fcntl does not exist there, and no cross-platform equivalent is claimed because none could be tested
