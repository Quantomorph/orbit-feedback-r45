# ORBIT

An offline research prototype for auditable execution and risk controls in a proposed crypto-futures trading system.

This snapshot is shared for engineering feedback only. It is not a deployed trading bot, a profitability claim, or a production-ready system. It contains abstract and test adapters, durable audit records, reconciliation, and risk checks. It does not include a real exchange integration or authorize demo or live trading.

## What to review

We are especially interested in concrete counterexamples, reproducible defects, and clearer safety boundaries:

1. Can a crash or restart make recorded intent disagree with recovered state?
2. Can stale, missing, or contradictory exchange observations pass the risk gate?
3. Do writer fencing and durable intent checks hold when workers overlap?
4. Which tests demonstrate behavioral guarantees, and which only check implementation details?

See [the architecture](docs/ARCHITECTURE.md), [known limitations](docs/STATUS.md), and [how to give feedback](CONTRIBUTING.md).

## Design context

The design targets OKX BTC-USDT perpetual swaps, with Claude (an LLM) as a proposed decision layer that has no authority of its own: deterministic Python owns risk, sizing, exchange state, reconciliation, writer authority and recovery. A test-file docstring also names a GPT model used for an earlier review. This snapshot contains no venue adapter and no model integration.

`orbit/risk/limits.py` holds the frozen limits of a historical experiment, A1: DEMO environment only, 8 USDT planned risk per trade, 5x maximum leverage, 20 USDT maximum realized daily loss, and at most two entries per UTC day. These are historical assumptions recorded in the code, not recommended settings.

The code and tests in this snapshot were generated by AI coding sessions under the project owner's direction, and AI models were also used as reviewers. No human code contributors are known.

This project is not affiliated with, sponsored by, or endorsed by OKX, Anthropic, or OpenAI. Their names are used only to describe the design and how it was developed.

## Running the tests

Use Python 3 on Linux, WSL2, or a Linux container, with files on a local filesystem. Native Windows is unsupported for journal execution because it requires POSIX locking. The runtime permits macOS development, but does not claim it as a supported deployment target. Do not use network-mounted journal storage.

From the project root in a POSIX shell:

```sh
PYTHONDONTWRITEBYTECODE=1 sh RUN_TESTS.sh
```

These are offline tests; no credentials, model connection, or real exchange adapter are needed.

The historical acceptance record reports 22 suites and 1,242 passes at the source checkpoint. An independent AI-assisted rerun of these exact source bytes on 2026-10-13 (Linux 6.18, ext4, Python 3.13.16) reproduced 22 suites, 1,242 passed, 0 failed, exit 0. Its complete output is in [docs/TEST_RUN_LINUX_20261013.txt](docs/TEST_RUN_LINUX_20261013.txt). No minimum Python version has been established.

Green tests are evidence about this checkpoint's behavior, not a comprehensive safety verdict.

### Supplemental scripts

`RUN_TESTS.sh` runs only `tests/test_*.py`. These scripts run separately from the project root:

```sh
python3 tests/repro_daily_figure_divergence.py
python3 tests/repro_n1_state_divergence.py
python3 tests/repro_r45_future_dated_view.py
python3 tests/repro_checkpoint_regression.py
python3 tests/stress_journal_checkpoint.py
```

In the 2026-10-13 rerun each exited 0; the stress script completed 2,400 appends with 0 failures. Their individual logs are not included.

### Historical reproducer caveat

`tests/repro_before_a1.py` is a historical reproducer written against an earlier harness. Its F2 line still prints `DEFECT REPRODUCED`, but the label is stale: the current harness defaults a fill's execution time to its commit time, so the script's gain is now recorded as executed today, and allowing the entry is correct. Passing an execution time of yesterday (`exit_exec` in `Rig._synth_round_trip`) with a commit time of today produces `REJECTED DAILY_LOSS_REACHED` and zero adapter calls. For current cross-midnight evidence, use `tests/test_safety_closure_r4c4_a1.py` and `tests/repro_daily_figure_divergence.py`. The historical script is kept byte-exact.
